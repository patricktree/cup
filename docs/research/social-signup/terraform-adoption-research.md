The earlier RealIanX provider link does not substantiate domain management: that provider advertises templates, segments, topics, automations, and events. The y0n0zawa provider actually covers domains/API keys/verification. It is a small independent project, not an official Resend provider; repository popularity is not reliability evidence. Pin a published version, review the chosen version's domain import/read behavior, and require a clean post-import plan. Do not claim production maturity from source inspection alone. [RealIanX repository](https://github.com/RealIanX/terraform-provider-resend), [y0n0zawa repository](https://github.com/y0n0zawa/terraform-provider-resend).

Supabase previously had a masked-OAuth-secret drift bug reported with 1.7.0; the issue is now closed through linked fix #312. Verify the selected release contains the fix and test repeat planning before relying on secret management. This is a release-validation requirement, not a reason to disable drift checks. [Upstream issue and fix link](https://github.com/supabase/terraform-provider-supabase/issues/310).

Keep the already working Resend sending key and Worker secret intact during adoption. A sending-only key is not a domain-management credential; infrastructure management needs a separate appropriately authorized credential. Do not attempt to reconstruct its secret through import or rotate it merely to adopt Terraform. Resend distinguishes full-access and sending-only permissions and optionally restricts sending keys to a domain. [Resend API-key reference](https://resend.com/docs/api-reference/api-keys/create-api-key).

## State backend choice

| Option        | What is supported                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Remaining burden                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HCP Terraform | Managed state/history, access controls and encryption at rest. Local execution can use HCP state while providers run on Patrick's machine; HCP state locking is supported by default. [State documentation](https://developer.hashicorp.com/terraform/cloud-docs/workspaces/state), [security model](https://developer.hashicorp.com/terraform/cloud-docs/architectural-details/security-model), [locking overview](https://developer.hashicorp.com/terraform/intro/phases/collaborate). | New organization/workspace and account authentication; confirm desired region and applicable plan during setup. Local mode does not supply remote execution or eliminate secrets contained in state.                                                                                                                                                                                                        |
| Cloudflare R2 | Official Cloudflare guide documents the Terraform S3 backend with bucket-scoped credentials. R2 currently supports conditional `PutObject`, including `If-None-Match`, which is the primitive required for S3 lockfiles. [Backend guide](https://developers.cloudflare.com/terraform/advanced-topics/remote-backend/), [compatibility table](https://developers.cloudflare.com/r2/api/s3/api/).                                                                                          | Configure `use_lockfile = true` and prove concurrent-lock rejection using the selected Terraform version before adoption. R2 lacks S3 bucket versioning; arrange separate protected state snapshots/recovery. HashiCorp tests its S3 backend only against AWS and gives no compatibility guarantee for alternatives. [Terraform S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3). |

Do not confuse R2 bucket retention locks with Terraform's state concurrency lockfile. Do not copy the Cloudflare guide's inline credential example into committed configuration. Use backend credentials through environment/configuration outside version control. Terraform warns that inline or backend-config credentials can persist in the local Terraform directory and saved plans. State and plans can contain configured provider secrets even if their terminal display is marked sensitive. [Terraform backend guidance](https://developer.hashicorp.com/terraform/language/backend/s3).
