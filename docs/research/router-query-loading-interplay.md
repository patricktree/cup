## Question

How do TanStack Router's route `loader`s, `pendingMs` / `pendingMinMs`, preload settings and its use of React transitions interact with TanStack Query's `ensureQueryData`, `prefetchQuery` and `useSuspenseQuery`? When does a navigation keep the previous screen in view, and when does it show the route's pending fallback or a Suspense fallback? And which practices for loading behaviour do the React, TanStack Router and TanStack Query docs and their authors recommend for client-rendered apps on touch devices?

## Answer

- **The router commits a navigation only once every route on the new path has finished its blocking work** (its loader and its code-split chunk). Until then the previous screen stays rendered. The commit itself runs inside `React.startTransition`.
- **The router shows a pending fallback only for a route with a `pendingComponent`** (or a router-wide `defaultPendingComponent`), and only after `pendingMs`; the fallback then stays for at least `pendingMinMs`. Without a pending component, the router keeps the previous screen for as long as the loader takes, with no time limit. Cup defines no pending component, so its `defaultPendingMs: 0` and `defaultPendingMinMs: 0` have no effect today.
- **A Suspense fallback inside the new screen is a React decision, not the router's.** A transition keeps already-revealed content in place, but a Suspense boundary that mounts for the first time during the transition shows its fallback at once. Cup's detail view wraps its content in its own new `<Suspense>`, so a suspending `useSuspenseQuery` shows the skeleton immediately, transition or not.
- **`useSuspenseQuery` suspends only when its query has no data.** With cached data it renders at once and refetches in the background if the data is stale. `useInfiniteQuery` likewise reports `isLoading` only without data.
- **Both symptoms come from the query client's `gcTime: 0`.** Leaving Recents removes the history query after a zero-delay timer, so returning shows "Loading tracks…". Suspense mode raises a query's `gcTime` to at least 1,000 ms, so an audiobook left for more than a second is removed too, and reopening it suspends into the skeleton. The router's own match cache does not help: it keeps only routes that have a loader.
- **Preloading only fills a cache that outlives the preload.** Router preloading runs `beforeLoad`, loaders and chunk loads. Routes without a loader preload only their chunk. A loader that puts data into the Query cache needs a `gcTime` long enough for the data to survive until the component mounts; with `gcTime: 0` it would be removed as soon as the fetch settles and nothing observes it.
- **`intent` preloading on a phone fires on `touchstart`, with no delay**, so it gains roughly the duration of the tap. `viewport` and `render` preload without any touch. The Android back button and browser history traversal never preload; only the cache can make them instant.
- **In Query 5.104, `ensureQueryData`, `prefetchQuery` and `fetchQuery` are deprecated** in favour of `queryClient.query(...)` (with `staleTime: 'static'` for the `ensureQueryData` behaviour). The current TanStack Router guide uses `queryClient.query` in its loader example.

## How a navigation renders

### The router's load and commit

[`runClientTransaction`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L1820-L1939) awaits the whole lane of matches (every `beforeLoad`, loader and route chunk), waits out any `pendingMinMs`, and only then commits the new matches through `router.startTransition` ([L1892-L1903](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L1892-L1903)). The React adapter implements `router.startTransition` with `React.startTransition` ([`Transitioner.tsx`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/react-router/src/Transitioner.tsx#L31-L37)). While the lane loads, the router's `status` is `'pending'` and `useRouterState` exposes `isLoading` ([`stores.ts`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/stores.ts#L114)), which could drive a subtle pending signal.

Whether a match blocks the commit is decided per match ([L806-L866](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L806-L866)):

- A match without loaded data (first visit, or not in the router cache) always blocks.
- A cached successful match reloads only when it is older than `staleTime` (or `preloadStaleTime` for a preload) and the route is being entered, its params changed, or a reload is forced. Such a reload runs in the background by default (`staleReloadMode: 'background'`, stale-while-revalidate) and does not block; `'blocking'` makes it block.
- The router caches a match after navigation only if its route has a loader, for `gcTime` (default 5 minutes) or `preloadGcTime` for preloaded matches ([L1652-L1680](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L1652-L1680)). Routes without a loader are never cached.

### The pending fallback: `pendingComponent`, `pendingMs`, `pendingMinMs`

[`offerPending`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L1466-L1566) runs while a lane loads. For the first match that is not yet successful, it looks up `pendingComponent ?? defaultPendingComponent`. If there is none, it returns without doing anything: the router never replaces the previous screen while loading. If there is one, it waits `pendingMs` from the start of the navigation, then publishes the matches with that match set to `pending`, again inside `startTransition`. Once React has rendered the fallback, `pendingMinMs` starts; the final commit waits for it ([`awaitPendingMinimum`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L1585-L1614)).

A pending match renders by throwing the transaction's promise ([`MatchInner`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/react-router/src/Match.tsx#L217-L227)), which the route's own `<Suspense fallback={pendingComponent}>` catches. The router wraps a route in that Suspense boundary only when it has a pending component or `wrapInSuspense` ([`matchView`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/react-router/src/Match.tsx#L99-L158)); otherwise the nearest boundary is the one the root `<Outlet>` places around its child, with `defaultPendingComponent` (or nothing) as the fallback ([`Outlet`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/react-router/src/Match.tsx#L319-L325)).

Library defaults are `pendingMs: 1000` and `pendingMinMs: 500` ([`router.ts`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/router.ts#L1220-L1222)). The data-loading guide explains them as a guard against a pending flash: show the pending component only for loaders slower than 1 s, then for at least 500 ms ([TanStack Router, Data Loading](https://tanstack.com/router/latest/docs/framework/react/guide/data-loading#avoiding-pending-component-flash)). Cup's `0` / `0` would show a pending component immediately and drop it the moment data arrives, if one existed.

### React: which Suspense boundary shows its fallback

The React docs state the rule the router builds on ([`<Suspense>`](https://react.dev/reference/react/Suspense)):

- During a transition, React keeps already-revealed content instead of replacing it with a fallback ("Preventing already revealed content from hiding"). A transition "only waits long enough to avoid hiding already revealed content".
- A Suspense boundary that is new in the transition does not wait: "any newly rendered `Suspense` boundaries will still immediately display fallbacks".
- Urgent (non-transition) updates never hold content; React shows the fallback.
- Fallback reveals are throttled to at most one every 300 ms.
- Suspense-integrated routers are expected to wrap navigations in transitions, and to reset a boundary with a `key` when navigating to different content.

`useTransition` takes no timeout ([`useTransition`](https://react.dev/reference/react/useTransition)); a transition held by already-revealed content waits until the data arrives, however long that takes. A time limit has to come from somewhere else, such as the router's `pendingMs`.

### TanStack Query: when a component suspends or shows a loading state

- `useSuspenseQuery` throws (suspends) only while the result `isPending`, that is, while the query has no data ([`shouldSuspend`](https://github.com/TanStack/query/blob/29859ae60c8dca0a5cdbf8abccc775b655cf43e2/packages/react-query/src/suspense.ts#L49-L53)). Cached data, even stale, renders at once; a stale query refetches in the background on mount ([Important Defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)).
- In suspense mode, `staleTime` and a numeric `gcTime` are raised to at least 1,000 ms, "to prevent unnecessary refetching when components remount after suspending" ([`ensureSuspenseTimers`](https://github.com/TanStack/query/blob/29859ae60c8dca0a5cdbf8abccc775b655cf43e2/packages/react-query/src/suspense.ts#L21-L47)).
- A query is removed `gcTime` after its last observer unsubscribes or its last fetch settles, if no observer is left by then ([`removeObserver`](https://github.com/TanStack/query/blob/29859ae60c8dca0a5cdbf8abccc775b655cf43e2/packages/query-core/src/query.ts#L523-L546), [`fetch`](https://github.com/TanStack/query/blob/29859ae60c8dca0a5cdbf8abccc775b655cf43e2/packages/query-core/src/query.ts#L816-L817), [`scheduleGc` / `optionalRemove`](https://github.com/TanStack/query/blob/29859ae60c8dca0a5cdbf8abccc775b655cf43e2/packages/query-core/src/removable.ts#L23-L39)). A query's `gcTime` only ever grows: each new set of options takes the maximum of the old and new value ([`updateGcTime`](https://github.com/TanStack/query/blob/29859ae60c8dca0a5cdbf8abccc775b655cf43e2/packages/query-core/src/removable.ts#L33-L39)).
- The Query docs suggest wrapping updates that change a suspending query's key in `startTransition` to keep the previous UI, since `placeholderData` is unavailable in suspense mode ([Suspense guide](https://tanstack.com/query/latest/docs/framework/react/guides/suspense)).

### Combinations, and what the listener sees

| Route setup                                                                                      | First visit                                                                                                                                                                    | Revisit with data in the Query cache                                                               |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| No loader; component uses `useSuspenseQuery` inside its own new `<Suspense>` (Cup's detail view) | Commit is immediate; the new boundary shows its fallback at once                                                                                                               | Renders cached data at once; background refetch if stale                                           |
| No loader; component uses `useQuery` / `useInfiniteQuery` (Cup's Recents)                        | Commit is immediate; the component renders its own `isLoading` state                                                                                                           | Renders cached data at once; background refetch if stale                                           |
| No loader; `useSuspenseQuery` with no Suspense boundary of its own                               | Suspends to the nearest already-revealed boundary (the root `<Outlet>`'s); inside the transition React keeps the previous screen, with no time limit                           | Renders cached data at once                                                                        |
| Loader awaits `queryClient.query` (or `ensureQueryData`); no pending component                   | Previous screen stays until the data arrives, with no time limit; then the new screen renders with data                                                                        | `staleTime: 'static'` / `ensureQueryData`: no wait. `query` with stale data: waits for the refetch |
| Same, with a `pendingComponent` and `pendingMs: N`, `pendingMinMs: M`                            | Previous screen stays up to N ms; then the pending component for at least M ms                                                                                                 | As above; no pending component when the loader returns at once                                     |
| Loader starts `queryClient.query(...)` without awaiting it                                       | Commit is immediate; the component suspends on the in-flight query (fallback rules as in the first rows), but the request started earlier, and on `touchstart` with preloading | Renders cached data at once                                                                        |

The `staleTime` passed to `queryClient.query` decides whether a revisit waits: the loader blocks the commit until the promise resolves, and a stale entry makes `query` resolve only after its refetch. Returning cached data without waiting (`staleTime: 'static'`, or `ensureQueryData`) leaves the refresh to the component's observer, which refetches stale data on mount.

## Preloading

- **Triggers.** `<Link>` with `intent` preloads on `mouseenter` and `focus` after `preloadDelay` (default 50 ms), and on `touchstart` immediately; `viewport` uses an `IntersectionObserver` with a 100 px root margin and the same delay; `render` preloads once when the link mounts ([`link.tsx`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/react-router/src/link.tsx#L364-L423), [`handleTouchStart`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/react-router/src/link.tsx#L459-L476); [Preloading guide](https://tanstack.com/router/latest/docs/framework/react/guide/preloading)). `router.preloadRoute(...)` preloads imperatively.
- **What a preload does.** It runs the same lane as a navigation with a preload flag ([`preloadClientRoute`](https://github.com/TanStack/router/blob/c79c620bf479cf53d64fb301407c2206922c0b4a/packages/router-core/src/load-client.ts#L2099-L2160)): `beforeLoad`, loaders (`preload: true` in their context) and route chunks. Cup builds with `autoCodeSplitting`, so even a route without a loader preloads its component chunk. Cup's root `beforeLoad` returns early for preloads.
- **Freshness with an external cache.** Router-cached preload data is fresh for `preloadStaleTime` (default 30 s) and kept for `preloadGcTime` (default 5 min). The guide recommends `defaultPreloadStaleTime: 0` with libraries like TanStack Query so that every preload calls the loader and the library decides whether to fetch ([Preloading guide](https://tanstack.com/router/latest/docs/framework/react/guide/preloading)). Cup already sets this; with Query `staleTime: 0`, every preload of a route with a loader would request again.
- **Preloads and `gcTime`.** A preloaded query has no observer until the component mounts. Query removes it `gcTime` after its fetch settles ([Prefetching guide](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching), and the `fetch` source above). With `gcTime: 0`, the data would be removed on the next timer tick, before a later tap could use it. A loader that awaits during navigation is also exposed: the removal timer runs between the loader's resolution and the transition's commit (derived from the source, not observed).
- **Touch.** `touchstart` is the only intent signal on a phone. The Android back button, the browser's back and forward, and links in non-`<Link>` elements bypass preloading.

## Established practices

Each item names who recommends it; the map's tickets decide which Cup adopts.

- **Avoid a skeleton flash for fast loads: delay it, then hold it.** TanStack Router's defaults (`pendingMs: 1000`, `pendingMinMs: 500`) exist for this ([Data Loading guide](https://tanstack.com/router/latest/docs/framework/react/guide/data-loading#avoiding-pending-component-flash)). React throttles Suspense reveals to one per 300 ms for the same reason ([`<Suspense>`](https://react.dev/reference/react/Suspense)).
- **Hold the previous screen during a navigation.** React expects Suspense-enabled routers to wrap navigations in transitions so revealed content is not replaced, and suggests `useTransition`'s `isPending` for a pending indicator ([`<Suspense>`](https://react.dev/reference/react/Suspense)). The hold applies only to boundaries that were already revealed; to hold, the suspending component must sit under such a boundary, or the route must block in its loader.
- **Stale-while-revalidate on revisits.** Query's defaults keep inactive data for 5 minutes and refetch stale data in the background when a component mounts ([Important Defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)). The router's loader cache does the same with `staleReloadMode: 'background'` ([Data Loading guide](https://tanstack.com/router/latest/docs/framework/react/guide/data-loading)).
- **Let the router decide when to fetch and the Query cache decide what is fresh.** The Router guide's TanStack Query example loads data in the loader with `queryClient.query({ ...options, staleTime: 'static' })` and reads it with `useSuspenseQuery` in the component ([External Data Loading](https://tanstack.com/router/latest/docs/framework/react/guide/external-data-loading)). The Query docs present router-level prefetching as the way to avoid request waterfalls, awaiting critical data and starting non-critical prefetches without awaiting ([Prefetching guide](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching#router-integration)). TkDodo (Query maintainer) argues the same split for React Router: the loader fetches early, Query caches, and the component keeps a query observer for background updates ([React Query meets React Router](https://tkdodo.eu/blog/react-query-meets-react-router), 2022).
- **Set `defaultPreloadStaleTime: 0` with an external cache**, so the cache's own `staleTime` governs ([Preloading guide](https://tanstack.com/router/latest/docs/framework/react/guide/preloading)). Preloaded or prefetched data needs a `staleTime` above 0 to avoid refetching right away, and a `gcTime` long enough to survive until use ([Prefetching guide](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching)).
- **Preload without hover.** Touch intent (`touchstart`, no delay), `viewport` and `render` are the Router's hover-free strategies, and `router.preloadRoute` or `queryClient.query` can preload imperatively for a likely next screen ([Preloading guide](https://tanstack.com/router/latest/docs/framework/react/guide/preloading), [Prefetching guide](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching)). Their request cost is the map's open question on mobile preload triggers.
- **Keep a screen alive instead of refetching it.** React 19.2 added `<Activity mode="hidden">`, which keeps a subtree's state and DOM but destroys its effects and re-creates them when shown, and can pre-render hidden content that reads Suspense-enabled data ([`<Activity>`](https://react.dev/reference/react/Activity), [React 19.2](https://react.dev/blog/2025/10/01/react-19-2)). TanStack Router 1.170 has no `Activity` integration (no reference in its source).

## Options for the map

Facts the later tickets can build on, not decisions:

- Raising `gcTime` (globally or per query) above the time a listener spends away from a screen is the precondition for rule 1 (revisit) in every design; without it, no router setting makes a revisit instant.
- Rule 2 (first visit) has two mechanisms: a blocking loader plus a `pendingComponent` with `pendingMs` / `pendingMinMs` (router-owned timeout), or no loader with the suspending component under an already-revealed boundary (React-owned hold, no timeout). Cup's detail view currently has neither, because its boundary is new on each visit.
- Rule 3 (cold start) needs no hold: on the first render there is no previous screen, so the router or Suspense fallback shows.
- Loaders that await with stale-allowed reads (`staleTime: 'static'`, `ensureQueryData`) make revisits instant and leave refreshing to the component's observer; loaders that await `query` with a finite `staleTime` make a stale revisit wait for the network.
- `<Activity>` could keep Recents mounted while the detail view shows, at the cost of hidden effects and polling behaviour the map lists as open.

## Limits
