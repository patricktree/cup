# Turbo changed packages between two commits

> Historical investigation, incorporated 2026-11-11. It is the evidence behind the rejected package-overlap option in [ADR 0021](../adr/0021-rerun-the-merge-gate-only-after-a-git-conflict.md), which holds the decision. The project did not use Turbo to decide merge gate reruns: it reruns the merge gate only after a git conflict, so none of the special cases below (`.patricktree-stack` pointer bumps, the hidden root package `//`, `wrangler.jsonc`) were built. [Original](https://github.com/patricktree/cup/blob/ee3e11fcac2a09334eda9c948be720308af06756/docs/research/turbo-changed-packages-between-commits.md) on the unmerged branch `research/turbo-changed-packages-between-commits`.

Research date: 2026-11-11, for [issue #259](https://github.com/patricktree/cup/issues/259) of the [merge gate rerun map](https://github.com/patricktree/cup/issues/258). Repository observations are from `origin/main` at [`65043649`](https://github.com/patricktree/cup/commit/65043649). Tool version: Turbo 2.11.7. Source references point at the [`v2.11.7` tag of `vercel/turborepo`](https://github.com/vercel/turborepo/tree/v2.11.7).

Evidence comes from three commands, run from a checkout of `65043649` against pairs of real commits on `main` and against synthetic commits, each a single-file change on top of `65043649` that was never pushed:

```sh
turbo ls --output=json --filter="[$A...$B]"      # changed packages only
turbo ls --output=json --filter="...[$A...$B]"   # plus their dependents
TURBO_SCM_BASE=$A TURBO_SCM_HEAD=$B turbo ls --output=json --affected
turbo query "query { affectedPackages(base: \"$A\", head: \"$B\") { length items { name reason { __typename } } } }"
```

## Question

For two arbitrary commits A and B, can Turbo list the packages changed between them, with and without their dependents? Which root or global files make Turbo report every package as affected? Where does a file outside every package land?

## Answer

1. **Yes, both.** `turbo ls --filter='[A...B]'` lists only the packages with a changed file (or a changed lockfile resolution); `--filter='...[A...B]'` and `turbo ls --affected` with `TURBO_SCM_BASE=A TURBO_SCM_HEAD=B` add every transitive dependent and gave identical results in every probe. `turbo query affectedPackages(base, head)` returns the dependent set too, but tags each package with its reason, so `FileChanged` and `LockfileChanged` are the direct set and `DependencyChanged` the dependents.
2. **The range is a merge-base diff, not a two-tree diff.** Turbo runs `git diff-tree --merge-base A B`, so it lists what B changed since its merge base with A. Swapping A and B gives a different answer.
3. **Only three things make everything affected** in this repo: `turbo.jsonc` (a hard-coded global file), a file matching `globalDependencies` that lies outside every package, and any file inside a package the root `package.json` depends on, directly or transitively (`@cup/config-oxlint` and six `.patricktree-stack` packages). The lockfile, root `package.json`, `pnpm-workspace.yaml`, `.gitattributes` and `.gitmodules` do not.
4. **A file outside every package lands on the root package `//`**, which `turbo ls` never prints, so `docs/`, `AGENTS.md`, `terraform/`, `supabase/`, `.claude/`, `knip.ts` and root config files report zero packages. `qa/` has no such files: every directory under it is a workspace package.
5. **Two traps.** A `.patricktree-stack` submodule pointer bump reports nothing, though it changes packages every package depends on. And Turbo reads the package graph, `turbo.jsonc` and the "current" lockfile from the working tree, not from B, so a correct answer for an arbitrary B needs a checkout of B.

## How Turbo maps changed files to packages

- **Changed files.** With both ends given, Turbo runs `git diff-tree -r --name-only --merge-base A B` ([`git.rs` L556–609](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-scm/src/git.rs#L556-L609)); without `TURBO_SCM_HEAD` it compares with `HEAD` and adds uncommitted and untracked files. An unknown ref or a too shallow clone makes every package changed (`GitRefNotFound`, [`change_detector.rs`](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-scope/src/change_detector.rs#L176-L205)). The official [`--filter` docs](https://turborepo.dev/docs/reference/run#microsyntaxes-for-filtering) describe the range only as `[<from commit>]...[<to commit>]` and do not mention the merge base.
- **`turbo.json` and `turbo.jsonc` first.** If either root file changed, every package is changed, before any other check (`DEFAULT_GLOBAL_DEPS`, [`change_mapper/mod.rs` L24 and L143–155](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/change_mapper/mod.rs#L143-L155)).
- **Deepest owning package next.** A file belongs to the deepest package directory that contains it ([`package.rs` L83–113](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/change_mapper/package.rs#L83-L113)). Inputs and their `!*.md` exclusions play no part, so a README-only change marks the package. `globalDependencies` is consulted only for files that no package owns ([`package.rs` L189–215](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/change_mapper/package.rs#L189-L215)): a match makes everything changed, anything else goes to the root package `//`. That is why `wrangler.jsonc`, a global dependency inside `apps/cloudflare-worker`, marks only its package, although it changes every task's cache hash.
- **Root dependencies.** If the owning package is one the root package depends on, every package is changed (`RootInternalDepChanged`, [`mod.rs` L254–293](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/change_mapper/mod.rs#L254-L293)). In this repo that set is `@cup/config-oxlint` and `@patricktree-stack/{config-oxfmt,config-oxlint,config-typescript,config-vitest,mermaid-check,submodule-check}` (`turbo query 'query { package(name: "//") { allDependencies { items { name } } } }'`).
- **Lockfile.** A changed `pnpm-lock.yaml` marks `//` (`ConservativeRootLockfileChanged`, [`package.rs` L130–151](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/change_mapper/package.rs#L130-L151)), and Turbo then parses the lockfile at A and marks each package whose resolved external dependencies differ (`LockfileChanged`). Only when the previous lockfile cannot be read or parsed does it fall back to every package ([`mod.rs` L160–222](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/change_mapper/mod.rs#L160-L222)). A specifier-only change with the same resolution marks no package.
- **Dependents.** `...[A...B]` and `--affected` add every transitive dependent; the [`--affected` docs](https://turborepo.dev/docs/reference/run#--affected) call the default equivalent to `--filter=...[main...HEAD]`.

## Traps for a "can conflict" rule

- **The submodule pointer is invisible.** Git reports a submodule bump as the single path `.patricktree-stack`, which no package directory contains, so it lands on `//`. Yet the bump changes the files of `@patricktree-stack/*` packages, six of which are root dependencies that make everything affected when changed in place. A rule built on Turbo's output has to treat a `.patricktree-stack` change as "everything" itself, or expand it with `git -C .patricktree-stack diff --name-only <old> <new>`.
- **The working tree decides the graph and the lockfile's "after".** Turbo builds the package graph and reads `turbo.jsonc` from the checkout it runs in, and compares the lockfile at A with the checkout's lockfile, not B's ([`javascript.rs` L298–322](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-repository/src/package_graph/javascript.rs#L298-L322), previous content from `from_ref` in [`change_detector.rs` L133–174](https://github.com/vercel/turborepo/blob/v2.11.7/crates/turborepo-scope/src/change_detector.rs#L133-L174)). The Playwright bump `1025c958` showed it: 6 lockfile-changed packages from a checkout of `1025c958`, 10 from a checkout of `main`, the extra four from lockfile changes made after `1025c958`. The `knip.ts` probe showed it for `globalDependencies`: an uncommitted edit of `turbo.jsonc` changed the answer for two committed refs. Run the comparison in a worktree of B.
- **Root-level files report zero packages.** A rule that reads only `turbo ls` misses changes to `knip.ts`, `oxlint.config.ts`, root `package.json` scripts, `pnpm-workspace.yaml`, `.gitattributes` and `docs/`, which Turbo marks only as `//`. Several of these feed root checks of the gates (Knip, format, lint configuration, `docs:check`). Use `turbo query` and treat `//` as a package of its own, or diff the root files directly.
- **Transitive sets overlap almost always.** Most libraries reach `@cup/web-app`: `@cup/errors`, `@cup/duration-ledger`, `@cup/rolling-limits` and `@cup/drizzle-migrations` each have 16 dependents, `@cup/conversion-contracts` 18. Two pull requests touching `libs/errors` and `libs/duration-ledger` share all 16 dependents, while their direct sets `{errors}` and `{duration-ledger}` are disjoint.
- **Task-level `turbo query affected --tasks` did not help here.** For a README-only change in `libs/errors` it returned 75 tasks, most with the reason `TaskAllChanged`, although that package's task inputs exclude `*.md`. The cause was not investigated. The [`--affected` docs](https://turborepo.dev/docs/reference/run#--affected) name `futureFlags.affectedUsingTaskInputs` for input-aware selection, which this repo does not enable.

## What this means for the merge rule

Turbo can produce the direct changed set between the merge gate's tested base and the new `origin/main`, and between that base and the pull request head: `turbo query affectedPackages`, keeping `FileChanged` and `LockfileChanged`, including `//`, run in a worktree of the head being judged. Any `DefaultGlobalFileChanged`, `GlobalDepsChanged`, `RootInternalDepChanged`, `LockfileChangeDetectionFailed`, `LockfileChangedWithoutDetails` or `GitRefNotFound` reason marks every package, and a `.patricktree-stack` path in the diff has to be promoted to "everything" by the rule itself.
