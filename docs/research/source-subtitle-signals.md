# Source subtitle signals

> Historical research, incorporated 2026-10-29. Adopted as [ADR 0014](../adr/0014-cut-source-material-at-the-visible-headline-and-carry-the-source-subtitle-in-the-narration-document.md), built in [#130](https://github.com/patricktree/cup/pull/130); see [Conversion](../architecture/conversion.md#preparation). Cup differs from the recommendations below: Washington Post was recorded after all ([#107](https://github.com/patricktree/cup/issues/107)) and is accepted only through a `data-*` attribute word, since its metadata paraphrases the visible source subtitle; the accepted attribute words are only the fixture-proven `subtitle`, `subheadline`, `summary`, `desc` and `description` (no `dek` or `standfirst`); the candidate is the first prose block after the visible headline in document order, not within a header container; everything before the visible headline is cut from the source material; and the source subtitle is narrated as its own second synchronization unit, not inside the opening unit. Repository observations below describe `7ecc08d`.

## Question

Which page signals reliably identify the [source subtitle](../GLOSSARY.md), and which mislead: DOM proximity to the source title's `<h1>` and its class names, `og:description` and `meta description`, JSON-LD `alternativeHeadline` and `description`, and an LLM? Does today's narration content selection already narrate the source subtitle as a body paragraph? What does each signal cost in latency and money?

## Answer

- **No single signal is precise on its own.** The page metadata equals the visible source subtitle on two of five readable pages (derStandard, OpenAI). On Anthropic it repeats the source title, on Gates Notes it is a different, longer teaser, and on Cloudflare, which has no source subtitle, it is a paraphrase of a body paragraph. Using metadata alone would show a wrong subtitle on two pages.
- **The source subtitle is always the first prose block after the visible `<h1>`, inside the same header container**, on all four pages that have one, but not always its next sibling: Anthropic puts a date between them, and Cloudflare (no subtitle) puts the byline there. Class names identify it on three of four pages (`article-subtitle`, `…__summary`, `ArtDesc`); OpenAI's Tailwind classes say nothing.
- **A rule combining both is correct on all five readable pages:** take the first non-date, non-byline prose block after the visible `<h1>` within its header container, and accept it only if its text equals the page's `og:description`, `meta description`, `twitter:description`, JSON-LD `description` or microdata `itemprop="description"`, or its class or `itemprop` names it (`subtitle`, `dek`, `standfirst`, `summary`, `desc`, `description`), and it differs from the source title. It costs no network request and well under a millisecond. Two pages is a thin basis; the acceptance fixtures should grow before this is trusted.
- **Kickers are the main hazard above the title.** derStandard (`h2.article-kicker`) and Gates Notes (`.Arteyebrow`) both set a short line directly above the `<h1>`. Looking only after the `<h1>` excludes them.
- **Today's narration already speaks the source subtitle, as the second synchronization unit.** The production prompt asks Gemini to keep the "standfirst or summary", and the committed goldens for Anthropic and derStandard narrate it right after the source title. On derStandard the kicker `<h2>` is fused into the same unit as the subtitle ("Streit um Agrarhilfen\n\nDie Dürre …"). Removing the subtitle from the body will move a kicker onto whatever block follows it, unless the spec decides the kicker's fate too.
- **Gemini sees the class names but not the metadata.** The selection prompt keeps every attribute except native `id`s, and preparation drops `<head>` and all `<script>` elements, so `og:description` and JSON-LD never reach the model. An LLM-only detector inside the selection call therefore has the class and position signals but not the metadata cross-check.
- **Washington Post could not be read.** Akamai answered `Access Denied` (HTTP 403) to `curl`, the desktop browser and WebFetch, and the Wayback Machine has no snapshot. Search results show its document title is "These seven races will determine which party controls the Senate", unlike the visible headline "Seven races that will decide control of the Senate", so its metadata is SEO copy, not a mirror of the visible header. Production preparation will likely be blocked the same way.

Further observations:

- **derStandard's consent wall still carries the header.** Without a consent cookie, `curl` and the browser are redirected to `/consent/tcf/story/…`, whose `section.privacywall-story` contains the kicker, `<h1>`, subtitle and lead image caption before the consent `<h1>` "Willkommen bei DER STANDARD". The full article could not be read without accepting consent, which was not done. The August eval case shows the full article uses the same header markup plus microdata (`itemprop="headline"`, `itemprop="description"`).
- **No page uses JSON-LD `alternativeHeadline`.** Where JSON-LD exists, `description` mirrors `og:description`, so it adds nothing over the meta tags.
- **Gates Notes now has a hidden first `<h1>`.** The live page renders `h1.titleHide.Hidden` with the document title ("The choices we make about AI now are critical | Bill Gates") before the visible `h1.ArtHeadline`. The September fixture predates it. Today's [`extractSourceTitle`](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/prepare-source-material/src/prepare-source-material.ts#L393-L403) takes the first `<h1>` in the body HTML without checking visibility, so on the live page it would pick the hidden one, and a proximity rule anchored on it would find nothing after it. Proximity has to anchor on the visible headline; this also affects the source title itself.
- **`og:title` is not a reliable source title either**: OpenAI's carries the suffix " | OpenAI Developers", Gates Notes' and Washington Post's differ from the visible headline.

## Does today's narration speak the source subtitle?

Yes, as an ordinary body paragraph right after the source title:

- Preparation keeps it. [`cleanAudiobookSourceMaterialHtml`](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/prepare-source-material/src/prepare-source-material.ts#L487-L493) removes only `button`, `figure`, `footer`, `form`, `input`, `nav`, `noscript`, `script`, `style` and `svg` plus empty elements, so `<header>` and its subtitle survive.
- The [production selection prompt](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/src/production-narration-content-selection.ts#L26) says "Keep the work's title, standfirst or summary, useful byline …".
- [`createNarrationDocument`](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-document-creation/src/narration-document-creation.ts#L230-L262) emits the source title as unit 1 and skips the first heading equal to it; every other selected block follows as body units. Headings are held as pending and fused into the next block's unit.
- The committed goldens, produced by the production candidate, confirm it: [Anthropic](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/test/evals/cases/anthropic-demystifying-evals-for-ai-agents/expected.json) unit 2 is the summary; [derStandard](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/test/evals/cases/derstandard-source-with-navigation-noise/expected.json) unit 2 is the kicker plus subtitle; [Cloudflare](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/test/evals/cases/cloudflare-kitesurf/expected.json) unit 2 is the byline (no subtitle exists). No eval case covers OpenAI or Gates Notes; given the prompt, the subtitle is expected to be kept there too, but that is not measured.

For the spec, "never spoken again as a body paragraph" means: the selected element (or its text) has to be removed from the selected HTML before narration document creation, or the narration document creation has to skip it as it skips the title heading. Matching by element identity is safer than by text, because derStandard fuses the kicker into the subtitle's unit. Changing that output means regenerating the Anthropic and derStandard goldens, which is a paid eval run.

## What Gemini would see and do

The selection request sends the cleaned body HTML in chunks of at most 24,000 characters or 200 elements, up to six at a time ([`narration-content-selection.ts`](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/src/narration-content-selection.ts#L128-L131)). [`prepareSelectionPromptHtml`](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/src/narration-content-selection.ts#L595-L614) collapses whitespace and strips native `id`s but keeps `class` and `itemprop`. The request does not include the source title, `<head>` or scripts.

- **Strengths.** The model already distinguishes the summary from kicker, date and byline well enough to select it (goldens above), and it sees the class names that identify three of four subtitles. It would likely find OpenAI's classless subtitle by position, as a human would.
- **Weaknesses.** It cannot cross-check against metadata it does not receive. Only the first chunk contains the header, so a subtitle field would come from one chunk's response. Its precision on pages without a subtitle (Cloudflare's byline, a dateline, a teaser box) is unmeasured, and the map ranks a wrong subtitle worse than none. Any LLM detector needs eval cases for both presence and absence.
- **Not tested.** No ad-hoc Gemini request was made, so "what Gemini returns if asked" remains unmeasured; it needs eval cases and an explicitly approved paid run.

## Cost and latency

Prices from [ADR 0002](../adr/0002-use-gemini-for-narration-content-selection.md) and [`gemini-completion.ts`](https://github.com/patricktree/cup/blob/7ecc08dbd6f961c544c4ca99dd0cabd1f1881f5e/libs/narration-content-selection/src/gemini-completion.ts#L93): $0.75 per million input tokens and $3.75 per million output tokens until 2026-12-31, doubling on 2027-01-01. Token figures assume roughly four characters per token.

## Recommendation for the spec

Start with the deterministic rule in source preparation, anchored on the visible source title, with metadata equality or a subtitle-like class or `itemprop` as the acceptance test, and the source title and dates and bylines as rejections. It is free, adds no latency, keeps precision ahead of recall, and on the pages read here finds every subtitle while finding none on Cloudflare. Pass the detected element to narration so it is spoken once, in the opening unit, and removed from the body. Record the five pages (plus the derStandard eval case) as acceptance fixtures; Washington Post needs a capture from a browser that the site admits. Keep an LLM fallback as a later option, measured by evals for both presence and absence.
